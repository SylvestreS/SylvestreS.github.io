上一篇说区块链是一本「改不动的账本」。这篇来回答那个最关键的问题：**到底是怎么做到的**。

答案只有两个字：哈希。

## 哈希函数：给任意数据算出一个指纹

哈希函数能接受任意长度的输入，输出一个固定长度的字符串。它有四个性质，每一个都在为区块链服务：

1. **确定性**——同样的输入永远得到同样的输出。全世界任何人算，结果都一样。
2. **单向性**——从输出反推不出输入。知道指纹，画不出指纹的主人。
3. **雪崩效应**——输入改动一点点，输出面目全非。
4. **抗碰撞**——几乎不可能找到两个不同的输入得到同一个输出。

用 Node 试一下第三条，最直观：

```js
const crypto = require("crypto");
const sha256 = (s) => crypto.createHash("sha256").update(s).digest("hex");

console.log(sha256("SylvestreS"));
// 8c1f0a...（64 位十六进制）
console.log(sha256("SylvestreT"));
// 3b7e92...（完全不相干的另一串，没有任何一位的规律）
```

只改了最后一个字母，两个结果之间看不出任何关系。这一点非常重要——**它意味着攻击者无法通过「逐步逼近」的方式伪造数据**。

## 关键技巧：让每一页记住上一页

哈希本身只是指纹，还不构成「不可篡改」。真正让它变成链的是这个朴素的把戏：**计算当前区块的指纹时，把上一个区块的指纹也一起算进去**。

```js
const sha256 = (s) => require("crypto").createHash("sha256").update(s).digest("hex");

function makeBlock(prevHash, data) {
  const hash = sha256(prevHash + JSON.stringify(data));
  return { prevHash, data, hash };
}

const b1 = makeBlock("0".repeat(64), { from: "A", to: "B", amount: 10 });
const b2 = makeBlock(b1.hash,      { from: "B", to: "C", amount: 5 });
const b3 = makeBlock(b2.hash,      { from: "C", to: "D", amount: 2 });

console.log(b2.prevHash === b1.hash); // true —— 链是完整的
```

现在假设有人想偷偷把 b1 里的金额从 10 改成 999：

```js
b1.data.amount = 999;
b1.hash = sha256(b1.prevHash + JSON.stringify(b1.data));

console.log(b2.prevHash === b1.hash); // false —— 链断了
```

他改完 b1，b2 里存的 `prevHash` 就对不上了。他只好把 b2 也重算，然后是 b3、b4……一直到最新的那一页。**想要改掉历史中的一笔，就得重算它之后的所有区块**。

这就是「不可篡改」的全部秘密。注意措辞——它不是「改不了」，而是**「改的代价高到不划算」**。

## Merkle 树：让一个区块内的几千笔交易也有指纹

区块内部还有一层。一个区块可能装几千笔交易，如果每笔都单独算指纹再拼起来，验证起来很啰嗦。所以区块用**默克尔树（Merkle Tree）**把它们组织起来：

- 每笔交易算一次哈希，作为叶子节点
- 相邻两个哈希拼起来再算一次哈希，作为上一层
- 一层层往上，最后得到唯一的一个根哈希（Merkle Root）

这个根哈希就代表了这个区块里的全部交易。它的妙处在于：**要证明「某笔交易确实在这个区块里」，只需要提供从叶子到根路径上的几个哈希值，而不需要把整个区块翻一遍**。这对轻钱包（比如手机钱包）至关重要——它们不可能下载整条链。

> 术语：**Merkle Root** 就是区块里那几千笔交易的「集体指纹」。详见 Glossary 中的条目。

## 一个诚实的补充

看到这里你可能会觉得：既然这么安全，为什么还有那么多区块链被攻击的新闻？

因为**哈希只保护链上的数据，保护不了链下到链上的这段路**。谁把一筆现实世界的交易写进区块，这个「录入」的环节依然依赖人、依赖机构、依赖流程。这一点在后面聊 RWA（真实世界资产）时会变成核心问题——把一栋楼代币化，区块链能保证代币记录不被改，但保证不了「这栋楼真的存在」。
