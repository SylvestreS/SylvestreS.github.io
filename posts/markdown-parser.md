博客要能写 Markdown，但我不想为此引入依赖，也不想跑构建。于是自己写了一个够用的解析器。

## 思路：逐行扫描 + 占位保护

Markdown 渲染最大的坑是**嵌套**：代码块里的 `#` 不是标题，链接里的 `*` 不是斜体。

解决办法是两遍处理：

1. 先把围栏代码块（` ``` `）整块抠出来，替换成占位符
2. 处理完其他语法后，再把代码块塞回去

```js
const fences = [];
// 第一遍：抽出代码块（用 `{3}` 表示三个反引号，避免嵌套）
content = content.replace(/`{3}(\w*)\n([\s\S]*?)`{3}/g, (_, lang, code) => {
  fences.push({ lang, code });
  return `\u0000FENCE${fences.length - 1}\u0000`;
});
// 第二遍：处理其余语法（此时已不含代码内容）
// 最后：把占位符换回 HTML
```

## 行内语法

行内部分用正则依次替换，注意**先处理反引号**，否则链接里的代码会被二次解析：

```js
const inline = (text) =>
  text
    .replace(/`([^`]+)`/g, "<code>$1</code>")
    .replace(/\*\*([^*]+)\*\*/g, "<strong>$1</strong>")
    .replace(/\*([^*]+)\*/g, "<em>$1</em>")
    .replace(/\[([^\]]+)\]\(([^)]+)\)/g, '<a href="$2">$1</a>');
```

## 块级语法

块级按行判断，顺序很重要——引号块要在段落之前：

1. 标题 `#`
2. 分割线 `---`
3. 引用 `>`
4. 列表 `-` / `1.`
5. 其余都当段落

## 一个必要的防御

渲染前必须先转义 HTML 实体，否则文章内容里的 `<script>` 会真的执行：

```js
const escapeHtml = (s) =>
  s.replace(/&/g, "&amp;").replace(/</g, "&lt;").replace(/>/g, "&gt;");
```

## 写在最后

自己写解析器的目的不是重复造轮子，而是**搞清楚每个语法规则是怎么落地的**。写完这 150 行，我对 Markdown 的理解比用三年库都深。
